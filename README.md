# QwikLearn

**Learn Faster. Understand Better.**

QwikLearn is an AI-powered learning companion. Drop in a PDF, pasted notes, or an
article and QwikLearn organizes it into a **Study Space** with generated notes,
summaries, flashcards, quizzes, key concepts, and a chat assistant scoped to that
material.

## Visual identity

QwikLearn's UI leans into the physical feel of studying — index cards with
punched binder holes, highlighter-yellow emphasis swipes, and a deep-ink /
warm-paper palette. See `lib/core/theme/app_colors.dart` for the full token
system.

| Token          | Value      | Use                                   |
|----------------|------------|----------------------------------------|
| `ink`          | `#211F36`  | Primary text, dark surfaces, nav bar   |
| `paper`        | `#FBF7EE`  | App background                         |
| `paperDim`     | `#F1EBDB`  | Cards, chips, secondary surfaces       |
| `highlight`    | `#D8FF4F`  | Signature accent — progress, emphasis  |
| `coral`        | `#FF6B5B`  | Secondary accent / destructive states  |
| `lavender`     | `#C9C4FF`  | Avatars, soft accents                  |
| `sage`         | `#9FBF8F`  | Success / correct-answer state         |

Fonts: **Space Grotesk** (display), **Inter** (body/UI), **IBM Plex Mono**
(stats, scores, streaks — everything numeric reads like a scoreboard).

Signature components: `HighlighterSwipe` / `HighlighterProgressBar`
(`lib/shared/widgets/highlighter_swipe.dart`) and `BinderCard` / `BinderHoles`
(`lib/shared/widgets/binder_holes.dart`).

## Getting started

This repository ships the complete `lib/` source tree, `pubspec.yaml`, and the
Supabase schema. It does **not** include the generated native platform folders
(`android/`, `ios/`, `windows/`, `macos/`, `linux/`, `web/`) since those must be
generated by your local Flutter SDK/toolchain, not copied.

```bash
# 1. Create the platform scaffolding in this same folder
flutter create . --project-name qwiklearn --org com.qwiklearn

# 2. Install dependencies
flutter pub get

# 3. Configure Supabase — copy the example env and fill in your project values
cp .env.example .env
# then run with:
flutter run --dart-define=SUPABASE_URL=... --dart-define=SUPABASE_ANON_KEY=...

# 4. Run the schema in supabase/schema.sql against your Supabase project
#    (SQL editor, or `supabase db push` if you use the Supabase CLI)
```

## Status — what's real vs. mocked

- **Real:** app shell, routing, full theme system, all screens are wired and
  clickable end-to-end (splash → auth → home → study space → each tool →
  progress/profile), `AuthService` calls real Supabase auth methods.
- **Mocked (by design, for a clickable MVP):** `studySpacesProvider`,
  `flashcardsProvider`, `quizProvider` return in-memory sample data instead of
  querying Supabase. Each is a small Riverpod provider — swap its body for a
  `.from(table).select()` call one feature at a time; no screen code needs to
  change.
- **Not yet built:** the AI generation calls (`generateNotes`,
  `generateFlashcards`, etc.) that would populate a study space from an
  uploaded PDF/article — these should live behind Supabase Edge Functions so
  no AI API key is ever bundled into the app.

## Database

`supabase/schema.sql` creates every table (`profiles`, `study_spaces`,
`study_materials`, `notes`, `summaries`, `flashcards`, `key_concepts`,
`quizzes` + `quiz_questions` + `quiz_attempts`, `chat_conversations` +
`chat_messages`, `learning_progress`), enables Row Level Security on all of
them, and adds a `study-materials` storage bucket scoped per user folder.
